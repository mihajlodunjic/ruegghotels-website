# 03 — Acceptance criteria and QA plan

## Automated

- Static: TypeScript strict `tsc --noEmit`, ESLint, production build. No errors/warnings that conceal broken UI.
- Unit: reducer transition table, illegal events do nothing safely, menu pause/resume context, Book navigation, room B3 -> reverse -> hallway -> Continue order, Skip/Replay, reduced-motion, errors and retries.
- Integration: `HTMLVideoElement` mocked for deterministic events (play promises, pauses, time update, frame callback when available, `seeked` resolution, errors); no accidental autoplay on route return.
- Browser Playwright: desktop 1440×900 and 1920×1080; mobile 390×844 and 375×812. Screenshots of five frames, with stable test time and animation disabled during screenshot comparisons. Tests for navigation, deep linking, landscape, focus and touch.
- Accessibility: automated axe checks where possible + manual keyboard and screen-reader smoke test.

## End-to-end core flows

1. Initial static poster and right editorial hero appear without requiring video download; Step Inside starts film only after explicit input.
2. At ~10s Welcome appears, no portrait/text collision, Continue resumes; Our Story route works; return navigates safely.
3. At 17.125s B0 appears correctly and the right door maps to its shape. Click door and button trigger same room entrance.
4. V3 ends at B3; room info opens; Back exits via separately encoded reverse; user lands at hallway (not master start/end). Continue resumes main film toward table.
5. Without entering room, Continue takes visitor straight to table. In both paths final panel appears and all 3 hotel choices reach `/book` with the right selection.
6. Skip, pause, menu and autoplay rejection work at every applicable state; failed video shows poster and links rather than blank stage.
7. Navigation to `/partners`, `/book`, `/our-story`, `/contact` works directly from URL (SPA rewrite), from global menu and at finale.
8. Booking demo must not claim real inventory, prices, sent requests or finalized payment. Partners must not assert invented collaborations.
9. Mobile: original right door remains visible in contained 16:9 decision frame, large 44px Explore Room button is usable, finale panel scrolls independently of media state.
10. Reduced-motion: same chapter, booking and partner pathways accessible without video, and UI reveals have reduced/no animation.

## Visual QA on actual accepted media

- Do not compare against AI-generated synthetic mockup architecture; use real master/B0/B3 frames.
- Preserve mountains, RÜEGG plaque and entrance in hero; portrait/book/counter in Welcome; right door at hallway; bed/window at B3; table left at finale.
- Check font license, contrast over photography, long translated labels, 200% zoom, 390 px, 320 px and mobile landscape.
- Distinguish mockup-approved **direction** from exact implementation proportions; if conflict exists, document with screenshot and ask owner.

## Performance/privacy and release gates

- Verify poster LCP, network waterfall, deferred video download on non-home routes, media payload size, video startup on throttled network, graceful fallback and no obvious black frame in transitions.
- Prefer Web Vitals LCP <=2.5s, CLS <=0.1, INP <=200ms as aims; include measured environment/method and limitations.
- Accessibility: WCAG 2.2 AA-oriented navigation contrast/focus/pause. Test forms and contact labels; announce demo limitations clearly.
- Security: avoid secrets committed to Vite public env, no invented API endpoints, no analytics tracking before decisions, neutral server headers for static host.
- Build + lint + tests + browser smoke must pass, or provide explicitly enumerated blockers. No automatic merges.
